**Meshnet** — приложение для LoRa-радиоустройств с [MeshCore](https://github.com/meshcore-dev/MeshCore). Подключите совместимое устройство по **Bluetooth, USB или Wi-Fi** и обменивайтесь сообщениями через mesh-сеть без интернета. Переписка хранится на вашем компьютере или телефоне, а радио передаёт сообщения в эфир.

Мобильная версия называется **Ommesh**. Она использует тот же клиент и возможности, с интерфейсом, адаптированным для телефона.

## Возможности

| Чаты · Chats | Сеть · Mesh | Радио · Radio |
| :--- | :--- | :--- |
| Личные сообщения, каналы и комнаты | Люди, ретрансляторы и датчики на карте | Подключение, настройки радио и приложения |
| Статусы доставки и маршруты сообщений | Профили узлов, телеметрия и удалённое управление | Пресеты частот, уведомления и диагностика |

### Переписка с понятной доставкой

- **Личные сообщения и каналы.** Создавайте каналы или подключайтесь по имени и 128-битному ключу, общайтесь в комнатах и добавляйте контакты в избранное.
- **Статусы доставки.** Видно, какие сообщения отправлены, подтверждены, остались без подтверждения или завершились ошибкой, а также время получения подтверждения. Если известный маршрут не дал подтверждения, повторная отправка использует flood.
- **Путь сообщения.** Смотрите известные ретрансляторы, принятые копии и качество сигнала. Вместо хешей отображаются имена контактов, если соответствие однозначно.
- **Управление маршрутами.** Закрепите flood для контакта или задайте срок жизни изученного маршрута — общий и индивидуальный. После его истечения следующее сообщение сможет найти новый путь.
- **Локальная история.** Переписка хранится в IndexedDB отдельно для каждого радио. Опциональная замена похожих букв кириллицы на визуально одинаковые латинские символы экономит байты в сообщении.

### Карта и управление сетью

- **Интерактивная карта.** Узлы с опубликованными координатами, расстояние и направление до них, известные маршруты через ретрансляторы с координатами. Маркеры различаются по типу узла, тускнеют со временем и объединяются в группы при близком расположении.
- **Кеш карт.** Просмотренные тайлы OpenStreetMap сохраняются на устройстве: уже открытые участки карты доступны без подключения к сети.
- **Единый профиль узла.** Из чата, списка или карты можно открыть маршрут, запросить телеметрию, переименовать контакт, добавить его в избранное или передать контакт по радио.
- **Удалённое администрирование.** Вход на ретрансляторы, комнаты и датчики через ваше радио. Статус, недельная история заряда и уровня шума, соседи ретранслятора, права доступа, настройки и консоль. Для датчиков — минимум, максимум и средние показания за период.
- **Контроль запросов в эфир.** Удалённые запросы выполняются по одному в видимой очереди. Действия с передачей отмечены антенной; обновление статуса запускаете вы.

### Удобно на любом экране

- **На компьютере.** Список чатов, переписка и панель подробностей рядом, палитра команд и горячие клавиши.
- **Обновления Windows.** Каналы Stable/Dev, отключаемая автоматическая проверка, проверка подписи и установка по кнопке. Доступны без подключения радио; перед перезапуском сохраняются история и черновики.
- **На телефоне.** Нижние вкладки, выдвижной список узлов поверх карты, меню по долгому нажатию и возврат свайпом.
- **Светлая и тёмная темы.** One Light, One Dark, выбор по настройкам системы и изменение размера текста.
- **Настройки радио.** Имя, координаты, частота, полоса, SF, CR, мощность, правила добавления контактов и выдачи телеметрии, часы, объявления в эфир и тонкая настройка. Изменение частоты подтверждается кнопкой Apply; удалённая смена радиопараметров поддерживает пробный режим с таймером.
- **Уведомления и диагностика.** Уведомления о сообщениях и новых узлах, журнал событий и просмотр сырых кадров в hex.
- **Деморежим.** Знакомство с интерфейсом, виртуальными контактами, сообщениями и узлами без оборудования.

## Как начать

Скачайте [актуальную сборку для тестирования](https://github.com/cm4ker/meshnet/releases/tag/dev) или откройте [все релизы](https://github.com/cm4ker/meshnet/releases).

| Платформа | Bluetooth LE | USB serial | Wi-Fi / TCP | Доступные сборки |
| :--- | :---: | :---: | :---: | :--- |
| Windows | ✓ | ✓ | ✓ | Установщики x64 и ARM64 из CI |
| macOS / Linux | ✓ | ✓ | ✓ | Сборка оболочки Tauri из исходников |
| Android | ✓ | — | ✓ | Отладочный APK из CI; имя приложения — Ommesh |
| iOS | ✓ | — | ✓ | Сборка в Xcode на Mac; [мобильная документация](apps/mobile/README.md) |
| Браузер | Web Bluetooth¹ | Web Serial¹ | — | Готовый веб-клиент или локальный сервер разработки |

¹ Доступность браузерных подключений зависит от браузера и ОС. Используйте Chrome или Edge с поддержкой нужного API. Для Wi-Fi требуется companion-прошивка с поддержкой Wi-Fi; TCP-порт по умолчанию — `5000`.

1. Подготовьте радио с **companion-прошивкой MeshCore**.
2. Выберите доступный способ подключения и подключитесь. При Bluetooth-сопряжении введите PIN устройства, если появится запрос.
3. Meshnet загрузит контакты и каналы, затем прочитает очередь сообщений. **Chats** — для общения, **Mesh** — для обзора сети, **Radio** — для настройки устройства.

**Пока нет радио?** Запустите веб-клиент по инструкции ниже, откройте [localhost:5180/?demo](http://localhost:5180/?demo), выберите **Demo** и подключитесь к **MeshCore-demo**.

Страница `dev` ссылается на последний успешный Dev-релиз с установщиками Windows, отладочным Android APK и веб-клиентом. Каждый билд хранится отдельно; теги `vX.Y.Z`, совпадающие с версией в корневом `package.json`, создают стабильные релизы. Сборки pull request доступны в артефактах workflow. Сборка iOS и загрузка в TestFlight выполняются отдельно.

В Windows откройте **App updates** на экране подключения, **Update** в боковой панели или **Radio → About**. Проверка выполняется при запуске и раз в шесть часов; скачивание и установка — по кнопке. Для перехода со старой версии без обновлятора потребуется одна ручная установка. [Каналы, подписи и выпуск обновлений](docs/desktop-updates.md).

## Разработка

Используйте **Node.js 24** — эту версию использует CI — и **pnpm 10.17.1**, закреплённый в `package.json`.

```sh
pnpm install
pnpm web
```

Клиент доступен по адресу **http://localhost:5180**. Перед запуском сервера пакет протокола пересобирается автоматически.

| Команда | Назначение |
| :--- | :--- |
| `pnpm typecheck` | Проверка типов TypeScript во всём workspace |
| `pnpm test` | Тесты протокола, клиента и сессии без оборудования |
| `pnpm build` | Сборка общего пакета протокола и веб-клиента |
| `pnpm desktop` | Запуск десктопного приложения Tauri в режиме разработки |
| `pnpm desktop:bundle` | Сборка установщика для компьютера |
| `pnpm android` | Сборка и синхронизация клиента, открытие Android Studio |
| `pnpm ios` | Сборка и синхронизация клиента, открытие Xcode на macOS |

Для десктопа нужны Rust и нативные инструменты сборки соответствующей ОС. Установщики создаются в `apps/desktop/src-tauri/target/release/bundle`. Для мобильных приложений нужны Android Studio / Android SDK или Xcode; подробности — в [мобильной документации](apps/mobile/README.md).

<details>
<summary><strong>Подключить мобильную dev-сборку к локальному серверу</strong></summary>

Запустите `pnpm web`, затем при синхронизации мобильной оболочки укажите LAN-адрес компьютера в `CAP_SERVER_URL`.

```sh
# macOS / Linux
CAP_SERVER_URL="http://<your-lan-ip>:5180" pnpm mobile:sync
```

```powershell
# PowerShell
$env:CAP_SERVER_URL = "http://<your-lan-ip>:5180"
pnpm mobile:sync
Remove-Item Env:CAP_SERVER_URL
```

Для работы без сервера разработки уберите переменную и снова выполните синхронизацию: клиент будет встроен в приложение.

</details>

### Структура проекта

```text
packages/meshcore   Companion Radio Protocol, кадры и сессии без платформенного кода
apps/web           Общий клиент на React + TypeScript, сборка Vite
apps/desktop       Оболочка Tauri 2 для Windows, macOS и Linux
apps/mobile        Оболочка Capacitor 8 для Android и iOS (Ommesh)
docs/screenshots   Демонстрационные снимки для обеих версий README
```

Клиент выбирает транспорт во время выполнения. Десктопная и мобильная оболочки содержат один и тот же веб-клиент и предоставляют нативные подключения, уведомления и хранилище паролей.

## Протокол и оборудование

<details>
<summary><strong>Совместимость протокола и локальное хранение</strong></summary>

- Коды команд и структура кадров соответствуют `examples/companion_radio/MyMesh.cpp` из MeshCore **v1.17.1, версия протокола 13**. Клиент объявляет версию протокола **3**, начиная с которой кадры сообщений содержат SNR. Неизвестные кадры записываются в журнал, не вызывая аварийной остановки.
- Serial и TCP используют обрамление `'<'` / `'>'`, длину в little-endian и полезную нагрузку. В BLE один кадр передаётся одной записью или уведомлением через Nordic UART service.
- История сообщений хранится в клиенте отдельно для каждого радио. В самом радио остаются только ещё не прочитанные сообщения.
- Пароли узлов сохраняются в системном хранилище учётных данных на компьютере, защищённом хранилище на телефоне и хранилище браузера в веб-клиенте.

</details>

<details>
<summary><strong>Bluetooth-сопряжение и прошивка для USB</strong></summary>

- **Windows:** приложение выполняет сопряжение по PIN для зашифрованного UART-сервиса и может заменить устаревшую привязку после сброса или перепрошивки радио. Нативная реализация GATT после сопряжения читает характеристики из кеша Windows.
- **USB на nRF52:** для T-Echo, RAK4631, Heltec T114 и подобных плат нужна **прошивка `_usb`**. Serial-порт сборки `_ble` не передаёт companion-протокол.
- **Android:** BLE-плагин запрашивает MTU 512 байт; кадры companion-протокола могут достигать 176 байт. PIN вводится в системном диалоге сопряжения.
- **iOS:** оболочка включает фоновый режим `bluetooth-central`, чтобы поддерживать соединение при переключении между приложениями.

</details>
